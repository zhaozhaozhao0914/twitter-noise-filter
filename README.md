# twitter-noise-filter

一套基于规则硬过滤与 LLM 语义蒸馏的推特技术情报提取流水线。

最初写这个脚本是因为我关注了 300 多个技术号，每天在时间线上浪费两个小时，翻出来的大多是互推营销、自媒体情绪宣泄和卖课导流。真正包含代码、真实架构或踩坑账本的推文，往往被折叠在算法最深处。

这个项目做的事情很简单：**不靠肉眼刷推，用无头浏览器或公开接口抓取特定信源，剔除 90% 的垃圾信息，最后让大模型把剩下的推文浓缩成每天 3 条纯文本工程纪要。**

同时随附一份清洗后的 25 位高信噪比技术 Builder 离线索引库。

---

## 架构与处理流程

```text
[信源池 (List / 关注)]
       │
       ▼
[规则硬过滤 (硬编码正则)] ──(字符<300 / 无代码无链接 / 抽奖营销)──> [丢弃]
       │
       ▼ (保留~15%候选)
[LLM 语义蒸馏 (DeepSeek-V3 / Claude 3.5)] ──(无实操价值)──> [输出 PASS 丢弃]
       │
       ▼
[每日纯文本内参 (Markdown / 邮件 / 终端)]
```

### 踩过的坑与设计取舍

1. **为什么不用大模型做全量初筛？**
   最开始我试过把抓到的所有原始 Tweet 直接丢给大模型打分。跑了一周，API 账单花了三十几刀，结果发现 80% 的营销推文只要看长度（<200字）或者看正则（抽奖、关注转评、私信领资料）就能瞬间毙掉。用 LLM 筛垃圾纯粹是烧钱。现在第一层全用纯 Python 正则拦截。
2. **LLM 的幻觉与套话问题**
   即使输入包含硬核代码，很多模型也喜欢写一段类似“这段代码具有深远的现实意义，极大提升了研发效率”的废话。解决办法不是加提示词求它别写，而是**定死输出 schema**，并明确声明：通篇没有真实代码、明确架构或账本的，只准输出单行 `PASS`，直接丢弃该条推文。

## 核心 Prompt

用于每日自动化提取的系统提示词（已实测 DeepSeek-V3 与 Claude 3.5 Sonnet）：

```text
你是一名极其严格的基础架构与全栈研发工程师，对没有实操价值的空话、营销话术零容忍。
请评估输入的技术推文，并提取出最具工程价值的硬核事实。

【提取要求】
1. 解决的具体工程/商业问题（一句话概括核心场景，拒绝泛泛而谈）
2. 依赖的核心技术栈与库（列出具体的语言、框架、API或开源工具）
3. 可验证的实操步骤与落地逻辑（1-3条，只保留可复现的动作）

【硬性约束】
- 严禁出现“赋能、闭环、颠覆、抓手、底座、矩阵、天花板”等大厂黑话；
- 过滤掉所有无意义的情绪宣泄、互推吹捧与引流卖课话术；
- 若推文通篇没有真实代码、明确架构、真实账本或可验证逻辑，请直接且仅输出：PASS。
```

## 快速上手

运行环境要求：Python 3.10+。

```bash
# 安装最少依赖
pip install httpx pydantic

# 配置你的大模型 API Key（支持任何兼容 OpenAI 格式的端点）
export LLM_API_KEY="sk-..."
export LLM_BASE_URL="https://api.deepseek.com/v1"

# 运行每日过滤任务
python run_pipeline.py --input raw_tweets.json --output digest.md
```

如果你每天处理的推文少于 50 条，根本不需要跑定时任务，手动运行一次即可。
